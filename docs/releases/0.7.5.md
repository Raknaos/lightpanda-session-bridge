# v0.7.5 - the CDP proxy was handing out cookie values over HTTP

## The leak

`/v1/cdp` returned the CDP result verbatim, and the blocklist had only three
entries. Measured against the running relay with a valid token:

```
POST /v1/cdp {"method": "Network.getCookies", "params": {"urls": ["https://x.com/"]}}
  200  cookies=7  VALUES PRESENT: True
```

Every synced site's cookies, in plaintext, over HTTP, to any caller holding the
token. The whole product is built so values never leave the relay:
`/v1/sessions` returns hosts and counts, the diagnostic report masks
`session.json`, the popup never shows a value. `/v1/cdp` was the one hole in
that rule - and it is the most convenient endpoint an agent has.

`Network.clearBrowserCookies` was allowed on the same route, and
`Storage.clearDataForOrigin` reached Lightpanda: either can wipe state the relay
deliberately scopes per origin.

The token is a bearer secret in a local file, so this is not theoretical. A
token that leaks - a log, a shell history, an agent prompt - turns every synced
session into plaintext.

## The fix

- Refused: `Network.getCookies`, `Network.getAllCookies`,
  `Network.clearBrowserCookies`, `Storage.clearCookies`,
  `Storage.clearDataForOrigin`, `Storage.clearDataForStorageKey` - on top of the
  three existing entries.
- Added `route: "verify_cookie_names"`: returns `present` / `missing` / `checked`
  for a list of names, so an agent can still answer "am I logged in?" with no
  value crossing the wire. Ordinary methods still pass, pinned by a test so the
  blocklist cannot quietly become "refuse everything".

## Five more, from the same audit

- **`list_sessions` raced `clear_sessions`** - the reader held no lock while the
  writer mutated the dict under one. Measured 24 `RuntimeError: dictionary
  changed size during iteration` in 2 seconds; it now iterates a snapshot taken
  under the lock.
- **Import errors reported another site's storage** - `set_session` reset 2 of its
  4 per-request counters before the early `raise`s, so a refused import answered
  with the previous site's `expected` and `missing` key names, which the popup
  renders verbatim.
- **`_authorized` could raise** - `_load_secret()` only caught `FileNotFoundError`,
  so an unreadable secret file reset the connection instead of returning 401, on
  every guarded route, without a token.
- **`do_GET` had no deadline** - three `settimeout`s in `do_POST`, none in
  `do_GET`, so a relay that accepted the socket and never answered wedged the
  popup on "Checking..." with no escape.
- **The toast never rendered** - `<div id="toast">` is line 699, `<script>` is
  line 698, and `toastEl` was captured at module evaluation. Null for the whole
  session: "Tout retirer" cleared with no confirmation, and copy-diagnostic
  feedback was invisible.

## Verified

All six proven red individually. The toast needed a behavioural harness rather
than a grep - a source assertion stayed green under the sabotage because it only
read the text. The replacement runs the real toast code in Node against the real
DOM ordering, node absent at module evaluation and present afterwards:

```
correct  ->  {"shown": true,  "text": "second"}
sabotage ->  {"shown": false, "text": ""}
```

The concurrency test reproduces the original message verbatim:
`Lists differ: ['dictionary changed size during iteration'] != []`.

196 tests green, gate 28/28, popup still 563 px.

# v0.7.9 - one lock per dict: the session race only failed on Linux

## What happened

v0.7.7's first attempt at the `dictionary changed size during iteration` race was
wrong in a way no local run could see. `list_sessions` took `CDP_LOCK` to snapshot
the dict. But `clear_sessions` and the persisted-session restore write that same
dict under a *different* lock. Two locks guarding one dict protect nothing - and
Windows never surfaced it, because the GIL plus thread scheduling kept the window
unobservable in a local run.

Linux CI found it:

```
FAIL: test_listing_while_clearing_does_not_raise
AssertionError: Lists differ: ['dictionary changed size during iteration'] != []
```

This is the failure mode that keeps its own counsel: a local green run and a green
Windows test suite both mean "not observed here", never "cannot happen".

## The fix

One owner per piece of data. `SESSIONS_LOCK` guards `_SYNCED_SESSIONS`, and every
reader and writer goes through it - the snapshot in `list_sessions`, the target
list and the `pop` in `clear_sessions`, the write in `set_session`, the
`setdefault` in the restore path, and `/health`'s count via a `session_count()`
accessor.

## Two tests that had to be rewritten

The concurrency test mutated the dict **bare** - a state no production caller can
produce, since every writer in the server takes the lock. It was testing the
harness rather than the shipped locking. It now mutates under the lock, which is
the path a real request takes.

A second test was added, and it is the one that matters: a writer that
deliberately does *not* take the lock, with the requirement that `list_sessions`
still does not raise. A read has to be robust to a careless writer, not merely
assume discipline.

The AST guard pinning this only inspected assignments, so putting the reader back
under `CDP_LOCK` - the exact v0.7.7 state - kept it green. It now walks every
`Name`, `Attribute` and `Subscript` that touches the dict, and the sabotage names
the offending line:

```
AssertionError: Lists differ:
    [(1102, 'snapshot = [(o, list(c)) for o, c in _SYNCED_SESSIONS.items()]')]
    != []
```

Three tests in this file were decorative at some point in this session. Each was
caught only by deliberately breaking the fix and reading *why* the run went red -
and twice the reason was the harness, not the code.

221 tests green, gate 28/28.

# v0.7.14 — a route can widen the deadline it inherited, only on the record

## The gap

v0.7.12 gave `Handler` a class deadline of 15 s, so a socket that sends nothing
is released by `StreamRequestHandler.setup()`. Five routes then narrow it to 10 s
for their body reads — legitimate and strictly safer.

But nothing stopped a route from **widening** it. A `settimeout(600)` on one
path would not have reopened a hole in the class deadline for *other* paths; it
would have reopened it for itself, which is exactly what the deadline exists to
prevent. `/v1/cdp` already does this on purpose, at 30 s:

```python
if self.path == "/v1/cdp":
    ...
    self.connection.settimeout(30)     # navigate + settle + four injection rounds
```

That is a real requirement, not an accident. But it was a **number in a
function**, indistinguishable at a glance from an accidental one — and nothing
would have failed when someone added a second 600 s read.

## The fix

The exemption becomes a named constant beside its reason, and five tests read the
real values out of the source rather than retelling them:

```python
# The one route allowed to exceed the class deadline, with the reason.
DELIBERATE_WIDER = {"/v1/cdp": 30}
```

| Test | What it holds |
|---|---|
| `test_no_route_can_widen_the_deadline_without_being_declared` | no route exceeds its declared bound |
| `test_the_deliberate_wider_route_still_exists_and_is_bounded` | `/v1/cdp` still exists, still at 30 s, still ≤ 60 s |
| `test_every_widening_call_site_is_accounted_for` | no *widening* call sits outside a route (narrowing ones may) |
| `test_no_unrouteable_widening_call_is_silently_ignored` | the widest `settimeout` in the file, whatever its attribution |
| `test_the_class_deadline_is_still_present_and_sane` | 5 s ≤ `Handler.timeout` ≤ 60 s |

The second test exists because the first can pass vacuously: rename `/v1/cdp`
and the exemption silently covers nothing while every other check stays green.

## Writing the test found the shape the audit had guessed at

The delegated audit reported "L1428 = 30 s > 15 s" without being able to attribute
it to a route. Writing the guard forced the real shapes out:

- the dispatch is `if self.path == "..."`, not `if path == "..."` — the first
  regex matched nothing and reported **`/v1/cdp n'existe plus`**, a confident
  false negative about code that is right there;
- a `settimeout` inside a route body sits ~15 lines **below** its branch header,
  so "the last route mentioned before the call" attributes it correctly only by
  luck; beyond a 60-line window it is declared unattributable instead of guessed;
- a prose mention is not a call. The comment above the class deadline literally
  reads *"The settimeout(10) inside do_GET was already too late"*, and the first
  version counted that sentence as an unrouteable call site.

None of these were relay defects. All three would have made the guard blind.

## Second defect, found by running the gate: the rate-limit message lied

With the quota genuinely exhausted, the live gate skipped `main_tarball` and named
the reason. Following it down:

```
token present: True | core limit: 5000 remaining: 4999   <- authenticated, fine
latest_commit -> RuntimeError: GitHub API rate limit reached (anonymous is 60/hour per IP)
X-RateLimit-Remaining: 0 | X-RateLimit-Limit: 5000        <- the REAL error
```

The token was present and used; the 5000/h quota was simply exhausted by repeated
gate runs. And the message named the wrong one:

```python
_RATE_HINT = "GitHub API rate limit reached (anonymous is 60/hour per IP)"
```

A constant, raised on **every** 403/429. A user holding a valid token — which
raises their quota from 60/h to 5000/h — was told to add a token they already had.
Now derived from the error's own headers:

```
GitHub API rate limit reached (authenticated token: 5000/hour, 0 left)
```

**Identity comes from GitHub's number, not from the local token file.** The first
attempt read `bool(github_token())` and produced `anonymous: 5000/hour` — two
contradicting facts in one sentence, because a test-runner context has no token
file while the headers still said 5000. GitHub reports 60 for anonymous and
5000 for authenticated; that number *is* the authority.

Four new tests, one proven red. Two pre-existing tests asserted
`assertIn("60/hour", ...)` — they were pinning the lie. Realigned to the
intention ("the quota is named, with its real figure") and to fixtures carrying
real headers, because with empty headers the honest code can report no figure at
all.

`git checkout tests/test_updater.py` restored a botched in-place edit here — safe
only because that file had no uncommitted work, which is checked, not assumed.

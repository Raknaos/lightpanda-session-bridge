# v0.6.1 - the health endpoint tells the truth

## The defect

A dead TCP/WebSocket socket is still a live Python object. The relay used:

```python
if _CDP_TRANSPORT is not None:
    return          # "not None" was read as "usable"
```

So once Lightpanda or WSL went away, `_ensure_connection` kept handing out the
stale transport forever. Every following call raised on the dead socket. Only an
explicit resync (`_connection_resync`, added in v0.5.7) ever replaced it - which
is arguably why resync existed at all.

`/health` then compounded it, deriving its answer from a second flag:

```python
"attached": _CDP_SESSION_ID is not None   # never cleared on death
```

Result: the popup badge showed the relay online, `/health` returned
`200 attached=true`, and nothing worked. A health endpoint that reports success
is worse than one that is absent.

A third, quieter defect: `CdpTransport.request` skipped unsolicited CDP events
(no `id`) with no bound. A page logging to the console fast enough kept the
serving thread spinning until the socket timeout, on the thread that was meant
to answer the HTTP request.

## The fix

1. `CdpTransport` remembers that its socket died - on `OSError`, on a graceful
   close (`recv()` returning `b""`, which used to surface as a bare
   `JSONDecodeError` and so was not even recognised as a socket failure), and on
   an unbounded event storm. `alive()` is `not dead`: absence of evidence is not
   evidence of death, so a healthy idle transport still counts as alive.
2. `_ensure_connection` reopens only what proved itself dead. A healthy idle
   transport is never torn down - Lightpanda scopes its cookie jar per
   connection, so dropping it silently logs the user out of every synced
   session.
3. `health_payload()` is a real function, extracted from the inline handler, so
   the claim is asserted in a test instead of trusted by eye. It stays
   sanitized: no origin, no page URL, no cookie name, no token.

## Verified

- 9 new tests, each proven red without its fix: the dead socket is reused
  (`0 != 1`), `/health` claims `attached` over a dead socket, and the
  event-storm test hangs indefinitely - which is exactly the production symptom.
- The tests also pin the half that must NOT change: a healthy idle connection
  is preserved, and `/health` still reports `attached` when the socket works.
  A fix that simply always answered false would be a health endpoint lying the
  other way.
- 147 tests green, acceptance gate 28/28, CI green on `a19734f`.
- Confirmed against the live relay: after a restart it reports
  `attached=false, sessions=0` instead of a reassuring lie.

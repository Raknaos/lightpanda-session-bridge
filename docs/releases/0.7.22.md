# 0.7.22 — « à jour » et « la branche a avancé » ne sont pas la même nouvelle

## Le défaut

Le relais publie `shipped_tree: "same"` pour **deux situations matériellement
différentes**, et depuis l'ajout du bras `head == current` (addendum 0.7.21) la
seconde existe enfin :

| Situation | Ce qui est vrai |
|---|---|
| `main` a avancé, mais sur des commits hors `extension/` (depuis 0.7.19) | les octets déployés sont identiques, **la branche a bougé** |
| l'arbre déployé **est** la pointe de `main` (mesuré 0.7.21) | **rien n'a bougé du tout** |

Le popup traitait les deux par `updateSameBytes` :

> « Identique à la release publiée · **la branche a avancé** »

Pour un utilisateur entièrement à jour, dont la branche n'a pas bougé d'un
seul commit, l'affirmation est fausse — et fausse **précisément** dans le cas
où il a le plus de raisons de se fier à l'outil.

## Le correctif

Le popup sépare les deux sur une mesure qu'il possède déjà
(`current_commit` contre `latest_commit`), plutôt que d'inventer un état
supplémentaire côté relais : quand les deux commits sont égaux, c'est
`updateUpToDate` (« À jour · v0.7.21 ») ; sinon la phrase existante, qui
reste vraie.

La version manquante a un repli : `updateUpToDate` interpole la version, donc
`v` nu pour une version absente — le repli passe par la puce sans version.

## Preuve

`tests/node/test_update_card_truth.js` passe de 18 à **36** tests : les deux
situations rendent deux phrases **distinctes**, la phrase rendue est comparée
par **égalité exacte** à la chaîne du dictionnaire (une traduction reformulée
ne peut plus être passée sous silence), et le cas « branche avancée » est vérifié comme
restant vrai.

`scripts/proof_red_update_tip.py` : **3 sabotages, 3 rouges nommés, 0 invalide**,
`popup.js` restauré à l'octet près.

1. **A** — suppression du bras : la phrase « la branche a avancé » devient
   inrendable. Rouge : `si la branche a avance, il rend la phrase exacte du
   dictionnaire -> "À jour · v0.7.20" != "Identique à la release publiée · la
   branche a avancé"`.
2. **B** — inversion de la garde (`===` → `!==`) : les deux situations
   **échangent** leurs phrases, ce qui est pire qu'une branche manquante car
   les deux entrées rendent encore quelque chose de plausible. **4 rouges.**
3. **C** — suppression du repli de version : `meta="À jour · v"`.

Check de gate `the popup tells 'at the tip of main' apart from 'the branch
moved on'`, enregistré dans `LOCAL`, **influence prouvé** : un compte truqué dans
le harnais donne `3/5 named red` et `NOT READY`, exit 1.

## Deux erreurs de harnais trouvées en route

Elles sont le contenu réel de cette release ; le correctif produit tient en
douze lignes.

**Une assertion multilingue écrite à la main ne matche rien et passe quand
même.** J'ai écrit `!/avance|avanz|moved/i.test(meta)` — et le test est resté
**vert sur le code non corrigé**. Le français dit « avancé » (sans `e`), et
aucune des dix langues n'écrit « advance » : `avanzó`, `avançou`,
`weitergezogen`, `前进`, `進捗`, `avanzato`. Un motif bâti sur le vocabulaire
mental d'un auteur est une garde décorative déguisée en test. Le motif est
désormais **dérivé du dictionnaire sous test**
(`SAME_FR.slice(SAME_FR.indexOf('·'))`), et le cas positif compare par égalité
exacte.

**Deux sabotages ont rendu la sortie identique.** `if (atTip ||
shipped_tree === 'same')` est un élargissement réel, mais sur les entrées
utilisées il est indiscernable de la suppression du bras : les deux rendent
« À jour ». Ce n'est que la comparaison des deux sorties qui a révélé que mon
modèle du code était faux, pas le test. L'élargissement utile inverse la garde,
ce qui change **quelle phrase chaque entrée reçoit**.

Corollaire retenu : l'attente d'un sabotage est une sous-chaîne du **nom**
d'échec que la suite imprime réellement, jamais d'une paraphrase — une attente
trop étroite dégrade silencieusement un vrai rouge en `INVALIDE`.

## Gravé

- Point **65** : le mot écrit à la main dans une assertion multilingue ne matche
  rien et rapporte vert ; et un sabotage rouge peut viser la mauvaise assertion.
- Point **57** (corollaire ajouté) : ne jamais spend un point existant comme
  ancre de patch — cela l'a supprimé, vérifié par listing des numéros.
- Point **66** : les invariants structurels battent les invariants rapiécés.

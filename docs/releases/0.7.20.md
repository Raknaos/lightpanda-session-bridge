# 0.7.20 — le popup dit **pourquoi** il n'y a rien à installer

## Le défaut

0.7.19 a rendu le canal de mise à jour honnête : le relais mesure désormais que les
octets publiés sont identiques à ceux du poste. Mais cette mesure n'atteignait pas
l'utilisateur.

Quand `shipped_tree === "same"`, la pastille affichait :

```
A jour          <- la puce
commit 34827e4  <- la ligne du dessous
```

C'est vrai, et useless. `main` avance en permanence sur des commits qui ne touchent
que `docs/` ou `scripts/` — mesuré : `cb4bdf51` (« la branche SANS PROVENANCE
compare aussi les octets »). Un utilisateur qui lit `commit 34827e4` ne peut pas
distinguer :

- « rien de neuf pour toi » (les octets sont identiques)
- « un changement de code t'attend » (il y a bien un nouveau commit)

Ces deux états sont indiscernables sur la ligne affichée.

## Le correctif

Le popup traduit l'**état mesuré**, jamais la note du relais :

- `shipped_tree === "same"` → `updateSameBytes`, dans les dix langues
- sinon et un commit connu → `commit <sha>`
- sinon → `updateBaseline` (le cas « provenance inconnue », qui existait déjà)

Le commit reste lisible en infobulle — c'est la bonne place pour un détail d'équipe.

## Pourquoi ne pas afficher la note du relais

`note` vaut par exemple `main moved to cb4bdf51, but the deployed tree is
byte-identical` : un sha et de l'anglais. C'est juste pour un journal, faux pour un
panneau en dix langues. Le relais expose donc un **indicateur mesuré** (`shipped_tree`)
et le popup fait la traduction. Point du skill : *le popup montre vrai*, donc il
traduit un état, il ne recopie pas un diagnostic.

## Preuve

`tests/node/test_update_card_truth.js` — **18 verts** :
- `shipped_tree: 'same'` → la ligne dit « identique », pas un sha nu
- `shipped_tree: 'differs'` → la puce dit « Mise à jour » (l'inverse, sinon le
  correctif masque une vraie MAJ)
- `shipped_tree: null` → aucune identité affirmée sans mesure
- sans commit → pas de sha inventé
- la clé existe dans les dix langues, et le français ≠ l'anglais

**Trois sabotages rouges**, chacun nommant son propre défaut. **Check LOCAL
enregistré et vérifié influent** : le sabotage du popup fait passer le gate de
`READY` à `NOT READY` avec le message du défaut, en affichant l'ancienne valeur
mesurée (`meta = "commit 34827e4"`).

## Deux pièges de harnais (points 52/53 du skill)

1. `vm.runInContext` avec le **source** d'une fonction ne fait que la **définir**.
   Sans l'appel, tous les champs restent à leur valeur initiale — j'ai passera
   cinq itérations à accuser les accesseurs, qui étaient innocents.
   *Un champ vide = problème d'accesseur ; tous les champs vides = le code testé
   n'a jamais tourné.*
2. Un test qui n'exerce que le **nouveau** comportement laisse passer un harnais
   cassé. Ici les cas `differs` et `null` étaient déjà corrects avant le correctif :
   ils font échouer un harnais cassé sur une sortie **déjà bonne**, au lieu de le
   laisser passer en silence.
## Preuve visuelle (extension reelle, compositeur)

Le harnais de peinture lit desormais la carte de MAJ peinte. En simulant le cas
que le correctif vise — un commit installe anterieur, `main` ayant avance sur un
commit qui ne touche que `docs/` — le relais vivant repond
`shipped_tree: "same"`, `update_available: false`, et l'extension affiche :

```
puce       : A jour
meta       : Identique a la release publiee - la branche a avance
infobulle  : commit cb4bdf5
```

100 % francais, aucun litteral anglais, et la distinction est laissee au lecteur :
« rien de neuf » n'est plus la meme chose qu'« un commit a bouge ».

Piège rencontre pour produire cet etat : un sha de commit factice tronque a 33
caracteres au lieu de 40. Le relais ne l'a pas reconnu comme un sha et a pris la
branche « sans provenance », donc `shipped_tree` revenait `None` — la feature
paraissait morte. Un flag absent parce qu'injoignable et un flag absent parce
qu'inmesure sont identiques de l'exterieur (point 54 du skill).

`scripts/measure_real_popup_screencast.py` lit desormais `#update-chip`,
`#update-meta` et son infobulle : la preuve est celle du DOM peint, pas celle
d'un stub.

## Le relais mentait aussi (trouve apres la preuve visuelle)

En interrogeant le relais vivant apres la publication, la reponse etait :

```
shipped_tree     : None
shipped_tree_sha : None
local_tree_sha   : None
note             : "main moved to 0b6fc3b4, but the deployed tree is byte-identical"
```

Trois valeurs absentes, et une note qui affirme une comparaison que personne n'avait
faite. Le chemin rapide (commit installe = dernier commit livre) reutilisait le texte
du chemin lent, ou le hachage avait reellement eu lieu.

C'est le meme defaut que celui corrige dans le popup, produit par le relais : une
phrase non mesuree. Corrige :

| chemin | `shipped_tree` | `shipped_tree_sha` | note |
|---|---|---|---|
| rapide | `"unknown"` | `None` | « deployed commit X is the latest that touched extension/ » |
| lent, identique | `"same"` | present | « main moved to X, but the deployed tree is byte-identical » |

`shipped_tree` est desormais publie sur **les deux** chemins : c'est lui que le popup
interroge, donc « unknown » doit etre visible et non une cle absente.

Un test preexistant pinnait l'ancien mensonge (« byte-identical » sur le chemin
rapide) : migre vers le contrat mesure plutot qu'assoupli. Deux nouveaux tests dans
`TestNoteOnlyClaimsWhatWasMeasured`, 2 sabotages rouges ajoutes.

Le harnais de preuve a d'abord donne 2 rouges sur 2 - via un
`ModuleNotFoundError`, parce que le sabotage cassait l'import de `updater.py`. Point
57 : un exit 1 accompagne d'un echec d'import est un HARNIS, pas une preuve. Et un
sabotage cible une formule qui disparait des qu'on la reworde : ici PATCH-MISS sur
11 sabotages, 1 invalide. Points 56/57 consignes.

**11 sabotages, 11 rouges nommes, 0 invalide.** Gate : 35/35.

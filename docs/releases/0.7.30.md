# 0.7.30 — la carte nomme la version installée dès le premier cadre

## Le défaut, mesuré sur le vrai `init()`

`init()` écrivait la version du **pied** de page de façon synchrone, mais ne
rendait la carte de mise à jour qu'**après** `await loadBridgeToken()`, le
bootstrap et la sonde du relais.

`/v1/update/check` répond en **864 ms** sur le relais en service. Pendant toute
cette fenêtre, la carte affichait **`v0.5.0`** — le littéral de `popup.html` —
sur une extension installée en 0.7.29. Vingt-neuf versions de retard, sur le
panneau dont le seul but est de dire de quelle version vous êtes.

Le footer, lui, disait la bonne version : les deux nœuds étaient donc en
désaccord, et c'est celui qui mentait qui était le plus visible.

## Ce n'était pas nécessaire

`chrome.runtime.getManifest()` est une connaissance **locale**. Rien dans
l'identité de la carte n'attendait le réseau. Le correctif rend la carte tout de
suite, avec `updateInfo` encore `null` :

```js
renderUpdateCard();
await loadBridgeToken();
```

La puce est honnête entre-temps — « Relais hors ligne » signifie « je n'ai pas
encore été prévenu », la même règle que les points 64/67 côté relais.

## Le test mesure le premier cadre, pas un appel direct

`tests/node/test_card_identity_immediate.js` amorce chaque nœud avec le contenu
initial du **balisage** — donc l'état que l'utilisateur reçoit réellement — et
exécute le **vrai `init()`** avec un `loadBridgeToken` qui ne résout jamais, ce
qui reproduit exactement la fenêtre mesurée. Appeler `renderUpdateCard()`
directement aurait mesuré un état qu'aucun utilisateur ne voit.

6 verts, dont le cas déjà correct (le footer) pour qu'un harnais cassé se révèle
là plutôt que de passer en silence.

## Preuves

- `scripts/proof_red_card_identity.py` : **2/2 rouges nommés, 0 invalide**,
  `popup.js` restauré à l'octet, idempotent.
- Nouveau check `LOCAL` `card_names_the_installed_version_on_the_first_frame`,
  enregistré et **prouvé influent** : produit réellement saboté → `31 checks,
  NOT READY`, exit 1.

## Deux fautes qui ont retardé la preuve

- Mon premier sabotage réécrivait `appVersion` — la version du **pied** — alors
  que l'assertion lit `updateVersion`. Nœud différent : suite verte, preuve
  correctement refusée. Un sabotage doit toucher le nœud que l'assertion compare.
- Extraire une fonction du source avec `indexOf(header)` + `indexOf('\n}\n')` la
  tronque à la première ligne commençant par une accolade fermante, qui dans un
  corps imbriqué est une accolade **intérieure**. Symptôme : un
  `SyntaxError: Unexpected end of input` sans aucun rapport avec la tranche.
  Compter les accolades.

## La règle générale

Quand un point d'entrée écrit un nœud A de façon synchrone et un nœud B
seulement après une chaîne d'`await`, vérifier si B est dans la **même classe de
connaissance** que A. S'il l'est, l'asymétrie est le défaut. Un littéral de
remplacement dans le balisage est un **état**, pas une valeur neutre : le premier
rendu doit le posséder.

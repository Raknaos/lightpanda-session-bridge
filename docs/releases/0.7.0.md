# v0.7.0 - the popup shows what the relay reports

## The defect

v0.6.1 made `/health` honest. The popup never asked. `checkRelay()` was:

```js
const res = await fetch(`${RELAY}/health`, ...);
if (res.ok) { badge online; }
```

`res.ok` only means the HTTP request succeeded. The relay answering 200 while
its CDP connection to Lightpanda is dead is exactly the case v0.6.1 fixed - and
the popup still showed a green "Relay Online". A correct fix that never reaches
the user is not a fix.

## The fix

1. `checkRelay()` reads `attached` and falls back to the old behaviour when the
   field is absent, so an older relay keeps working.
2. A third badge state, `badge.idle`, in amber. Green would promise a sync that
   cannot succeed; red would report an outage that is not happening.
3. `relayIdle` in all 10 languages, short enough not to clip: the pill truncated
   "Relais pret - navigateur non connecte" mid-word. Caught by looking at the
   rendered screenshot, not by any test.
4. `preview_popup.py --state idle`, because a UI state with no preview is a
   state nobody reviews.
5. The gate's i18n check catches `t("key")` and two keys sharing a line - both
   proven red by sabotage before shipping.

## Also in this release

`--apply-update` followed `check_update`'s recommendation silently. Asking for
the published release could therefore install the main-channel tarball, whose
sha256 has no sidecar to verify against - reported honestly as
`checksum_verified: false`, with no way for the caller to say which they wanted.
`--channel release|main|auto` makes the choice explicit; `auto` is unchanged.

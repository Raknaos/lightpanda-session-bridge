# v0.7.17 — retracting v0.7.16: the wrong-language frame was never painted

## What v0.7.16 claimed

That `#diag-text` shipping `Copier le diagnostic` caused every English install to
see French flash on every open, and that the live gate now proved it.

## Why the claim was false

The measurement was `Emulation.setScriptExecutionDisabled` — load the popup with
script execution off, then compare the DOM to the settled DOM. Every string
differed, so it read as a defect:

```
element                1er rendu (sans JS)                apres rendu (avec JS)
#diag-text             'Copier le diagnostic'             'Copy diagnostic'  <-- FLASH
#label-update          'Bridge update'                    'Mise à jour du Bridge'  <-- FLASH
#btn-text              'Sync to Lightpanda'               'Synchroniser vers Lightpanda'  <-- FLASH
#footer-secure-tag     'Isolated Profile · Localhost CDP' 'Profil isolé · Localhost CDP'  <-- FLASH
```

**Disabling script execution proves the pre-translation DOM exists. It does not
prove a frame was presented.** And the document makes that decisive:

```
</head> = l.589, <body> = l.590, script src = [701]
script AVANT le body ? False
```

`popup.js` is a **parser-blocking classic script on line 701 of a 704-line
document** — the last thing in `<body>`. Chrome has every reason to hold the first
paint until that script has run, and to present only the translated panel.

## The measurement that settles it

`Page.startScreencast` streams one event per **composited** frame — what was really
put on screen. Driven against the **installed** popup on its real origin
(`chrome-extension://fcig…nino/popup.html`, not `file://`), with `fr` pinned and
confirmed read back:

```
popup INSTALLE : chrome-extension://fcig…nino/popup.html
langue demandee : fr | localStorage lu : fr
ce que le popup a resolu : {"stored":"fr","diag":"Copier le diagnostic"}
frames COMPOSITEES : 8
frames visuellement distinctes : 3
```

Three painted states — badge resolving, values filling in. Reading frame 0 with
vision: the language chip is **`FR`**, the footer button is **« Copier le
diagnostic »**, the card reads **« MISE À JOUR DU BRIDGE » v0.7.16**, and the
relay pill says **« Relais en ligne »**. **The first frame a user can see is
already fully French.** There is no flash.

A pixel diff alone could not have told us that: **30 % of pixels differed**
between two frames that were *both* French, because the badge and the origin
value had changed. Language has to be read, not inferred from a diff.

## The harnesses that produced it, and what was wrong with each

| Harness | Defect |
|---|---|
| `measure_first_paint.py` | Measured the DOM, reported it as paint. The root error. |
| `measure_first_paint_lang.py` | Same proxy, plus `file://` localStorage ≠ the extension's, so its runs disagreed with each other. |
| `measure_paint_frames.py` | Compared hand-picked y-bands; the `footer = 0.86–1.0` band was **empty** (panel is 501 px of 720, footer sits at 0.68) and reported `0% difference` for free. |
| `measure_screencast_frames.py` | Right instrument, wrong subject — `file://`, so a parallel run of the real extension rewrote the language mid-measurement and produced a bogus FR→EN flip. |
| `locate_ink_bands.py` | Correct diagnostic; it is what exposed the empty band. Deleted with the rest. |

All five are deleted. `scripts/measure_real_popup_screencast.py` is kept: real
origin, real artifact, language read back from the popup itself.

## The gate check is removed

A gate that can only add checks will eventually gate on a bug that was never
there. The v0.7.16 LIVE check is gone, and the retraction is in `CHANGELOG.md` so
the record is not quietly rewritten.

## What is kept, and why

The HTML literal changed to `Copy diagnostic`. It is a one-line change that makes
the untranslated panel match the default language (`en`), which is correct
regardless — but it is **not** presented as a bug fix, because there was no bug.

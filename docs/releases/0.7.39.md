# 0.7.39 — un verdict qui ne nomme rien

## Le défaut

Neuf checks lisaient l'échec d'une suite Node ainsi :

```python
failed = next((l for l in out if l.strip().startswith("FAIL")), "?")
```

Quand la suite meurt **avant** d'imprimer une ligne `FAIL` — `Cannot find module`,
une erreur de syntaxe, un binaire absent — la gate rapportait le littéral `?`.

Et onze checks voisins, dans le **même fichier**, faisaient déjà correctement :

```python
"printed no tally: %s" % (lines[-1:] or ["no output"])
```

Le placeholder n'était donc pas une convention : c'était neuf sites que personne
n'était allé corriger.

## Pourquoi `?` est le pire détail possible

Le verdict ne peut pas distinguer « je n'ai trouvé aucune cause » de « voici la
cause ». Un lecteur — ou l'agent suivant — n'a rien sur quoi agir. C'est un check
qui measure quelque chose en prétendant ne rien trouver.

## Le correctif

Un helper unique, `_node_failure(out, returncode, suite)`, qui retourne toujours
une cause **mesurée**. Exécution réelle sur quatre sorties :

| sortie | ce qui est rapporté |
|---|---|
| `FAIL   le badge ne se rafraichit pas` | `FAIL   le badge ne se rafraichit pas` |
| plantage module (3 lignes) | `test_x.js printed no FAIL line and exited 1 (3 line(s)); last: C:\x\crash.js:1` |
| **rien du tout** | `test_x.js printed NOTHING and exited 1 - it produced no FAIL line to read` |
| `ok  6 passed` | `test_x.js printed no FAIL line and exited 1 (1 line(s)); last: ok  6 passed` |

Corriger neuf sites d'appel est un nettoyage, pas un invariant. La règle est donc
assertée sur l'AST, sur chaque verdict retourné **et sur chaque helper qui
retourne une chaîne** : le placeholder d'un helper atteint un verdict sans jamais
passer par un tuple `("FAIL", detail)`, donc une garde qui filtre sur le tuple
n'en audite **aucun**.

## Cinq défauts dans la garde elle-même

Elle a d'abord été verte sur du code qu'elle prétendait voir, cinq fois de suite.
Chacun mesuré :

| version | erreur |
|---|---|
| 1 | filtre sur le tuple `("FAIL", detail)` → **0** des 4 sites réelles, `_node_failure` retourne une chaîne |
| 2 | `next\([^)]*"\?"` → ne matche rien : `[^)]*` ne franchit pas le `)` du générateur, qui précède le placeholder |
| 3 | signale **sa propre docstring**, qui cite le motif qu'elle traque |
| 4 | `TypeError: 'arguments' can't have docstrings` — `get_docstring` lève sur un nœud `arguments` |
| 5 | `ast.unparse` réécrit `"?"` en `'?'` → **un motif écrit avec les quotes de la source ne peut jamais matcher sa propre sortie** |

Le cinquième est le plus instructif : la garde utilisait une représentation que
l'outil ne produit pas. Deux règles en découlent — n'unparser que les
**feuilles d'expression** (`ast.walk` rend aussi les conteneurs, dont le texte
recontient la docstring), et matcher le caractère de quote de façon flexible.

**Un check qui signale sa propre documentation, ou qui plante, apprend à
l'ignorer — c'est pire que de n'avoir aucun check.**

## Discrimination mesurée

Sept directions, toutes prouvées :

| cas | attendu | obtenu |
|---|---|---|
| arbre sain | vert | `122 FAIL detail(s) are computed and none can go empty` |
| `return "FAIL", "?"` littéral | rouge | nomme la ligne |
| `next(..., "?")` dans un helper | rouge | `via next(..., <question mark>)` |
| `next(..., "?")` assigné à une variable | rouge | détecté via le corps |
| `lines2[-1]` sans repli | rouge | sous-script d'une liste vide |
| `?` dans une **docstring** | **vert** | documenter le bug n'est pas l'avoir |
| `next(..., '?')` quote simple | rouge | les deux formes reconnues |

## La leçon qui porte le plus loin

Une classe de caractères niée ne franchit pas un caractère de fermeture qui
apparaît avant lui. La même erreur, deux fois, en deux mots différents :
`[^;]*?` ne franchit pas le `;` qui termine `setTimeout(...);` (0.7.38 — un délai
de 0 ms passait), et `[^)]*` ne franchit pas le `)` qui ferme l'argument d'un
générateur (0.7.39 — un placeholder quatre lignes plus loin passait inaperçu).

Quand un motif échoue, afficher **quels nœuds il a matchés** — pas ce qu'on
croyait qu'il devait matcher.

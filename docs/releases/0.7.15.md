# v0.7.15 — the badge is the first thing read, and the only thing that went stale

## The defect

`checkRelay()` was called exactly once, in `init()`. The 30-second interval
refreshed only the session counter:

```js
setInterval(() => {
  if (document.visibilityState === 'visible' && bridgeToken) {
    refreshSessions();          // the count, not the badge
  }
}, 30000);
// checkRelay(): 1 call site, line 1142, inside init()
```

So the panel's headline — the one thing a user reads before anything else — was a
**single sample**. A relay that crashed, or a Lightpanda that restarted, after the
popup opened left "Relay Online" on screen for as long as the panel stayed open.

The sharper consequence: v0.6.1 added a third state on purpose — `idle`, amber,
"relay process alive but its CDP connection dead" — precisely because a red badge
there would report an outage that is not happening and a green one would promise a
sync that cannot succeed. That state was **unreachable** after the first few
hundred milliseconds of the popup's life. A correctness fix, shipped and verified,
that the product could not actually display.

There were no `visibilitychange` or `focus` listeners at all: reopening the popup
did not re-sample either, so reopening did not help.

## The fix

```js
setInterval(() => {
  if (document.visibilityState !== 'visible' || !bridgeToken) return;
  refreshSessions();
  checkRelay();                    // the badge is on the same cadence now
}, 30000);

let lastRelayCheck = 0;
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState !== 'visible' || !bridgeToken) return;
  const since = Date.now() - lastRelayCheck;
  if (since < RELAY_MIN_CHECK_GAP_MS) return;   // 2000ms floor
  lastRelayCheck = Date.now();
  checkRelay();
  refreshSessions();
});
```

Two budgets, deliberately: the interval is the steady cadence, and the
visibility listener is the reaction to the common case — something broke, the user
opens the popup to check. The 2-second floor exists because a popup can be closed
and reopened faster than 30 s, and each transition would otherwise fire its own
`/health`. A hidden or unpaired popup still spends nothing on the relay.

reverted.

## The harness gap, recorded because it reads as a product bug

Extracting the listener alone raised `lastRelayCheck is not defined`: the `let`
sits on the line immediately above the listener that reads it. Extracted in one
piece, the failure would have been attributed to the fix. Same family as skill
point 14 — a test must not import a smaller set of the module than the code
under test actually closes over.

# v0.7.8 - the DNS verdict cache had a TTL but was never pruned

## What was happening

`_DNS_CACHE` carries a `_DNS_CACHE_TTL` of 60 seconds, which reads like
expiration. It is not: the TTL only decided when an entry was *stale*, so a stale
entry would be re-resolved. Nothing ever removed one. The dict therefore grew for
the lifetime of the relay - one entry per distinct hostname ever submitted to the
origin check, forever:

```python
_DNS_CACHE[hostname] = (now, True)     # written, never dropped
```

Nothing else in the module grows. `_SYNCED_SESSIONS` is keyed by origin and
rewritten per sync, and the `_LAST_STORAGE_*` lists are reassigned, not appended
to. The DNS cache was the only unbounded container.

A single site that mints unique subdomains - asset hosts, tracking domains, cache
busters - is enough to grow it without limit, and the relay is a long-lived
process started by a scheduled task.

## The fix

Writes now go through `_dns_cache_put`, which purges entries older than the TTL
and caps the dict at 512. When it is full it evicts the oldest rather than
refusing to cache: a stale-free cache is not worth failing a legitimate origin
over.

## The test that was decoration

The first version of this test called `_dns_cache_put` directly - six tests, all
green. Then I reverted both production call sites to the pre-fix dict assignment
and re-ran: **still green**. The tests asserted that the helper worked, never that
the code called it, which is exactly the shape of a test that cannot fail.

Rewritten to drive `valid_origin()` - the function an incoming origin actually
traverses - the same sabotage fails with the defect named:

```
AssertionError: 1536 not less than or equal to 512 :
    le cache DNS depasse son plafond : 1536 entrees pour un plafond de 512
AssertionError: 51 not less than or equal to 2 :
    les entrees perimees n'ont pas ete purgees : 51
```

Two tests red, both pointing at the real cause. The suite also still asserts the
legitimate cases, so a cap cannot quietly break real origins: `github.com` is
accepted, `192.168.1.10`, `localhost` and `box.internal` stay refused, and a
cached verdict is still reused (the hostname resolves once, not twice).

219 tests green, gate 28/28.

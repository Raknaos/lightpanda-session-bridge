# 0.7.40 — un audit qui ne voit rien rapporte « tout va bien »

## Le défaut, une famille

Un check collecte des éléments dans le produit, applique des invariants, puis
compare. Si la **collecte** s'arrête — parce qu'une forme a changé dans le code —
tous les invariants s'appliquent à un ensemble **vide** et le check rapporte un
succès. Il n'a pas mesuré le produit ; il a mesuré le vide.

Deux checks avaient cette forme, tous deux sans garde :

```python
heads = re.findall(r"(?m)^## \[([^\]]+)\]", text)
...
return "ok", "%d entries, unique, descending, no welded heading" % len(heads)
```

Le message **annonce un compte**. Un compte qui baisse sans qu'aucun invariant ne
trouve rien, c'est la signature.

## Preuve mesurée

Sur l'arbre sain, `changelog_is_not_duplicated` dit `58 entries`. Trois titres
`## [` transformés en `# [` :

```
avant : ok   58 entries, unique, descending, no welded heading
apres : ok   55 entries, unique, descending, no welded heading
```

**Vert, et trois entrées perdues en silence.** Aucun doublon, aucun désordre,
aucune soudure : les invariants sont vrais du vide. C'est ce que le sabotage de
g41 a fait cette nuit sous une autre forme — un harnais dont l'ancre n'existait
plus mesurait un produit intact et le déclarait conforme.

Et un second trou, trouvé en corrigeant le premier : un titre qui perd son
crochet de fermeture (`## [0.7.38`) cesse de ressemble à un titre, donc la
**forme** disparaît du même coup que l'entrée. Une garde qui ne compare que deux
listes ne le voit pas.

## Le correctif

Deux gardes, calibrées sur ce qui disparaît réellement :

1. **Toute ligne qui ouvre une entrée de version doit la fermer.** Un `#`
   suivi de `[` et d'un chiffre, sans `]` : c'est un titre cassé, et il compte
   comme une perte.
2. **Toute ligne qui ressemble à une entrée doit être comptée.** Si 58 lignes
   ont la forme d'un titre et que 55 se parsent, la forme du fichier a changé —
   même si les 55 autres sont parfaitement saines.

Le même défaut dans `dom_ids_exist` : `wanted` et `present` peuvent tous deux
devenir vides, et `wanted - present` est alors vide. Le check disait
`31 ids referenced, all present` — les 31 venaient de la seconde regex, la
première était morte en silence.

Le message de FAIL dit maintenant ce qui est mesuré : les octets lus, ce qui a
été trouvé, et la phrase qui compte — **the check is blind, not satisfied**.
C'est la convention déjà présente dans `relay_error_translation_report`, qui
refuse `no relay error code could be read`.

## Ce qui n'était PAS un défaut

`i18n_parity` a exactement la même forme et **n'a pas** le défaut : `used`
— les appels `t('…')` lus dans le popup — est indépendant de `base`. Si `base`
s'effondre, les appels restent, et `unknown` non vide déclenche le FAIL. Mesuré :
indentation changée dans les 10 langues → `popup.js calls t('relayIdle') with no
translation`. Le découplage entre *ce qui est référencé* et *ce qui est défini*
est ce qui rend le check aveugle-proof, et il n'y était pas par hasard.

## Discrimination mesurée

| cas | avant | après |
|---|---|---|
| arbre sain | vert | vert |
| 3 titres `## [` → `# [` | **vert 55** | rouge, nomme |
| 1 titre seulement | **vert 57** | rouge, nomme |
| tous les titres | **vert 1** | rouge, nomme |
| `### [` sur un titre | **vert 57** | rouge, forme changee |
| crochet fermant perdu | **vert 57** | rouge, « never close it » |
| les deux aiguilles i18n mortes | — | rouge (déjà correct) |

## Le troisième défaut, trouvé en cherchant les deux premiers

`the_gate_cannot_contain_a_check_that_cannot_be_seen` — le check qui garantit
qu'aucun check ne peut être invisible au verdict — a exactement la même forme,
sur le sujet le plus grave possible.

`LOCAL` et `LIVE` vidés :

```
avant : ok   0 checks: every registered name resolves and is decorated;
                73 helpers are all called; nothing is neither
```

**Vert.** Le gate n'exécute aucun check et sa propre garde le compliments. Ses
invariants sont tous des tests d'emptiness — pas de check fantôme, pas de check
sans décorateur, pas de helper non appelé — et une inscription vide les satisfait
tous. C'est le défaut du `?` de 0.7.39, un cran plus haut : le verdict a la
forme d'une mesure et il n'y a rien derrière.

La correction refuse zéro check enregistré. **Partiellement** vide reste vert,
et c'est correct : 38 checks dans `LOCAL` seul, 16 dans `LIVE` seul, sont des
vrais chiffres.

## Ce que l'audit a réellement couvert

Onze checks ont une collecte dérivée de `re.findall`, `re.finditer`, `split` ou
d'une compréhension. Sur les onze :

| check | vide → |
|---|---|
| `changelog_is_not_duplicated` | **rouge** (corrigé) |
| `dom_ids_exist` | **rouge** (corrigé) |
| `the_gate_cannot_contain_a_check_that_cannot_be_seen` | **rouge** (corrigé) |
| `i18n_parity` | déjà rouge — `used` est lu dans le popup, `base` dans les données ; les découpler est ce qui le rend aveugle-proof |
| `relay_error_translation_report` | déjà rouge — `if not emitted: the guard is blind` |
| `proof_red_harnesses_are_required` | déjà rouge — `if not harnesses` |
| `single_relay` | déjà rouge — vide = rien n'écoute |
| `_release_asset` | déjà rouge — vide = asset absent |
| `every_shipped_relay_call_is_bounded` | déjà rouge — `if not files` |
| `unit_suite` | sans objet — collecte la sortie d'un subprocessus, pas un produit |
| `git` | sans objet — idem |

Trois corrigés, cinq déjà corrects, trois sans objet. Aucun laissé sur « ça
devrait aller ».

## Ce que l'audit a coûté

Sept collectes sans garde sont apparues dans un premier passage Regex. L'inventaire
par AST en a trouvé **onze** : le Regex en manquait la moitié, parce qu'il ne
reconnaissait ni les comprehensions ni les affectations en chaîne. C'est la même
erreur que le motif `[^)]*` de 0.7.39 — un motif qui ne voit pas la forme qu'il
cherche est un motif qui ne prouve rien.

Le premier audit annonçait « deux réels, un déjà correct, quatre non examinés ».
La version AST n'en a laissé aucun non examiné.

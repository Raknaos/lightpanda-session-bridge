# v0.7.1 - the report finally describes the relay that is running

## How it was found

`/health` and `/v1/diagnostics` disagreed, in the same process, at the same
instant:

```
GET /health          -> {"ok": true, "attached": true,  "sessions": 1}
GET /v1/diagnostics  -> {"cdp_attached": false, "synced_origins": 0,
                         "cdp_transport": "NoneType"}
```

Both are supposed to describe one relay. One of them was describing a module
that never executed.

## Root cause

`relay/server.py` is launched as the entry point, so Python registers its module
under `__main__`. `sys.modules` therefore has **no** `server` key. And
`_sibling("server")` looked only under `relay.server` and `server`:

```python
existing = sys.modules.get(dotted) or sys.modules.get(name)   # both None
return importlib.import_module(name)                          # loads it AGAIN
```

The second copy executed the whole file and got its own globals. Every field the
report claims to observe came from that copy: transport `None`, session id
`None`, synced sessions `{}`. The v0.6.0 fix for this exact class of bug
(`__import__` returning the package) fixed the *name* lookup but never the
`__main__` case, because nothing tests what happens when the module is the
program's entry point.

The fix compares `__main__.__file__` against `<diagnostics dir>/<name>.py`, so
the daemon reuses its own live module while a `python -m unittest` runner - also
`__main__` - cannot hijack the lookup.

## Two more, found on the way

**Two relays were running.** `allow_reuse_address = False` clears `SO_REUSEADDR`,
which stops a rebind after close but does *not* stop a second process binding a
socket that is already LISTENING. The watchdog and the scheduled task both
launched one in the same second (logged at 15:54:48); each kept its own copy of
the session state. `SO_EXCLUSIVEADDRUSE` is the flag that actually forbids it.

**`health_payload()` could kill its thread.** It called `transport.alive()`
directly; anything installing a transport without that method raised
AttributeError, and `do_GET` has no try around it.

**The watchdog called a broken relay healthy.** It accepted any 200 from
`/health`. Now it requires `attached: true` - and it no longer restarts the
relay when only Lightpanda is down, since the relay opens the CDP socket on
demand.

## Verified

- 14 new tests, each proven red without its fix (a second bind succeeding, the
  watchdog racing, `__main__` not reused).
- 161 tests green, acceptance gate 28/28.
- Live: a real import (2 cookies + 1 storage key) takes `/health` from
  `attached: false` to `true`, and the diagnostics report now agrees:
  `cdp_attached: true, synced_origins: 1` - with no cookie value in it.

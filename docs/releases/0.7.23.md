# 0.7.23 — « je n'ai pas pu vérifier » n'est pas « il n'y a rien »

## Le défaut

Quand GitHub répond pour la release mais **pas** pour la branche, `head`
revient `None` et `check_update` traverse **toutes** les branches — le même trou
qu'au moment du cas « à la pointe », un cran plus bas. Le relais répondait :

- `update_available: False`
- `shipped_tree: "unknown"`
- `note` : aucune

Et le popup affichait **« À jour »**. C'est exactement l'affirmation non
mesurée que 0.7.20 avait dû rétracter, qui rentre par une autre porte : la
recherche de release **avait** réussi, on est passé dessus. Le plus honnête
qu'on puisse dire est « aucune release publiée ne dépasse ce que vous avez » —
pas « rien n'a changé ». Un commit de `main` peut attendre, non lu.

Corrigé par un état propre (`unreachable_branch`, initialisé dans le dict de
départ donc `False` est délibéré, jamais absent), et une nouvelle phrase
traduite dans les **10 langues**, lue par le popup **avant** `atTip` — car sans
`latest_commit`, `atTip` est faux et la chaîne tombait sur la puce rassurante.

## Un second défaut trouvé par le même test

`check_update` faisait `head["sha"]` sans garde. Toute valeur truthy non-dict
renvoyée par `latest_commit` — une fonction, une liste — levait `TypeError`
**à l'intérieur** de la comparaison : un 500 sur le chemin de mise à jour du
popup. La fonction de production renvoie un dict ou `None`, donc aucun
utilisateur ne l'avait rencontré ; mon stub, lui, pouvait renvoyer un lambda.

`latest_commit` est une donnée externe : on valide sa **forme** à la frontière
(`isinstance(head, dict) and head.get("sha")`), pas seulement sa véracité.

## Trois tests verts qui ne mesuraient rien

Ma classe de test définissait `release_version="0.7.22"` alors que l'installé
était `"0.7.21"` : le bras `release_is_newer` répondait en premier et les
quatre tests passaient en exercant un chemin qu'aucun ne nomme. Visible
uniquement parce qu'une assertion (`shipped_tree == "same"`) a divergé.

Le défaut par défaut est maintenant aligné sur la version installée. Règle
générale : un test qui vise une branche doit rendre **toutes les autres
incapables de gagner d'abord**, et asserter la sortie de *sa* branche.

## Preuve

`test_updater.py` : 68 -> **72** tests. `test_update_card_truth.js` : 36 ->
**51** tests, dont l'inverse exigé : une clé absente (ancien relais) rend
exactement comme avant, et `unreachable_branch: False` ne change rien aux deux
cas mesurables.

`scripts/proof_red_unreadable_branch.py` : **3 sabotages, 3 rouges nommés, 0
invalide**, `relay/updater.py` restauré à l'octet.

1. **A** — suppression du bras : `AssertionError: False is not true : with
   head=None nothing marked the state as unread…`
2. **B** — suppression de la garde de forme : `TypeError: 'function' object is
   not subscriptable`
3. **C** — suppression de la clé initialisée : `AssertionError:
   'unreachable_branch' not found in {...}`

Check `an unread branch is reported, never read as 'up to date'` enregistré
dans `LOCAL`.

Le harnais voisin a signalé un **PATCH-MISS** pendant ce travail : son ancre
`if (atTip) {` était devenue `} else if (atTip) {` après l'insertion de la
nouvelle branche. Corrigé dans le harnais — c'est le trou que le `PATCH-MISS`
est fait pour voir.

## Un patch de skill qui a encore volé un point

Deux fois dans la même heure : écrire un nouveau point en remplaçant la
première ligne d'un point existant **supprime** ce point. Corrigé les deux fois,
et la règle est maintenant mécanique — si l'`old_string` commence un point
numéroté, on s'arrête. Le 63, disparu plus tôt pour la même raison, a aussi
été restauré.

Gravé : points **67** (résidu de chaîne), **68** (forme d'une donnée externe),
**69** (fixture qui teste un autre bras), **70** (attente recopiée d'un
commentaire, et lecture partielle de la sortie unittest).

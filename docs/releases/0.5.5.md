# v0.5.5 - "install the latest commit" works again

## The bug

Clicking **Installer le dernier commit** answered:

    Echec de la mise a jour : HTTP Error 415: Unsupported Media Type

GitHub said it, not the relay. The main channel downloaded its archive from
`api.github.com/repos/.../tarball/<sha>` while sending the
`Accept: application/octet-stream` header that was written for the CDN which
serves release assets. The API refuses a media type it cannot produce.

Measured on that exact URL:

| Accept sent | Answer |
| --- | --- |
| `application/octet-stream` | **415 Unsupported Media Type** |
| `application/vnd.github+json` | 200 |
| no Accept header at all | 200 |

The request died before a single byte of the archive was transferred, which is
why the failure came back in under a second and the extension never changed.

## The fix

The guard is in `_fetch`, the one place every update request goes through: if
the host is `api.github.com`, the Accept header is the GitHub media type, no
matter what the caller asked for. Download hosts keep the caller's Accept, and
they are right to - the CDN behind a release asset does serve octet-stream.

The release channel was never broken; only the main channel was. Both work now.

## Verify it yourself

    python -m unittest discover -s tests     # 95 tests, 1 skipped
    curl -X POST http://127.0.0.1:8765/v1/update/apply   # then /v1/update/check -> up to date

3 new tests pin the regression, including a behavioural one that captures the
real header sent on a stubbed socket.

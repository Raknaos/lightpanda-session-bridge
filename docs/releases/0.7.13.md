# v0.7.13 — a client that can wait forever has no honest state to be in

## The defect

The popup made **eight** `fetch()` calls to the local relay. Exactly **one** of
them carried a deadline — `/v1/session/import`, on a hand-rolled
`AbortController`. The other seven had no `signal:` at all.

`/v1/bootstrap` is the first of them. It runs before anything else, in `init()`:

```js
const res = await relayFetch('/v1/bootstrap', ...);   // used to be bare fetch()
// ... /health is never attempted
```

So a relay that accepted the socket and then said nothing left the popup with:

```
relayText  = "Checking…"     <- indefinitely, /health never tried
relayBadge = "badge"         <- neither .online nor .offline
origin     = ""              <- "Reading tab…" wiped to empty
status     = ""              <- empty
```

A user whose relay had wedged saw a badge that never resolved and an empty
panel, with no message and no way to tell "still working" from "dead". The
relay's own class deadline (15 s) could not help: the socket was healthy, the
*server* was silent in its handler.

## The fix

One helper, one deadline, every call:

```js
const RELAY_TIMEOUT_MS = 45000;

class RelayTimeoutError extends Error { ... }

async function relayFetch(path, options) {
  const controller = new AbortController();
  const deadline = setTimeout(() => controller.abort(), RELAY_TIMEOUT_MS);
  try {
    return await fetch(`${RELAY}${path}`, { ...opts, signal: controller.signal });
  } catch (err) {
    if (err && (err.name === 'AbortError' || err.name === 'RelayTimeoutError'))
      throw new RelayTimeoutError();
    throw err;
  } finally { clearTimeout(deadline); }
}
```

**45 s, deliberately longer than the relay.** The relay cuts a body read at
10 s and its class deadline is 15 s. A client that aborted *first* would replace
a translated reason — "this site origin is not allowed" — with a bare
`Failed to fetch`. The client's patience must outlast the server's cut-off for
the server's own error message to ever reach the user. There is a gate check
for exactly this ordering.

## The second defect: English in a ten-language popup

The relay answers in short codes. The popup rendered them verbatim:

```js
throw new Error(result.error || t('errRefused'));   // result.error always won
```

`origin refused`, `unauthorized`, `not found`, `update refused` — English
sentences inside a French popup. And `error.message || t('errRefused')` was
worse than dead: `message` is *always* truthy, so the translation fallback could
never fire.

Nine relay codes are now mapped to i18n keys in ten languages (56 keys × 10
languages, verified by parity check). An unrecognised code is still shown — it
is real diagnostic information — but framed by a translated prefix instead of
being dropped.

## The proof-red was itself broken twice, and both times the product was fine

Recorded because both shapes recur:

1. **A hung test prints nothing and scores as "no failure".** Under sabotage
   the pending `await` never settled, the async IIFE exited silently, exit code
   was **0**, stdout empty. The sabotage runner reported the test as *not
   proven*. The fix is a named assertion on cancellability *before* the await,
   plus a runner that refuses to score an empty-output run.

2. **A brace-less declaration breaks brace-walking.** `const RELAY_TIMEOUT_MS =
   45000;` has no `{`, so "find the next brace" walked into the following class
   and the extraction re-declared it — surfacing as `Identifier already
   declared`, which reads like a product fault and is a harness bug. The
   extractor now stops at `;` when a statement ends before any brace, and
   asserts the chunk declares exactly one symbol.

Three harness stubs were also lying about the runtime before the product code
ever got a fair test: an `AbortController` whose `abort()` **threw** (the real
one flips `signal.aborted` and notifies), a `fetch` that ignored its signal, and
`fetch(` counting that missed a call site. A stub that misrepresents the runtime
makes the test measure the stub.

# 0.7.25 — un échec d'installation nomme sa cause

## Le défaut, mesuré sur le vrai `popup.js`

`runUpdate` construisait correctement l'erreur, puis son propre `catch`
réécrivait le message **inconditionnellement** :

```
Échec de la mise à jour : Impossible de joindre le relais (est-il démarré ?)
```

Pour **onze** situations. Mesuré sur le fichier réel, avant correction :

| Situation | Ce que l'utilisateur lisait |
|---|---|
| somme de contrôle refusée | Impossible de joindre le relais |
| archive invalide (traversée de chemin) | Impossible de joindre le relais |
| rien à installer | Impossible de joindre le relais |
| dossier d'extension absent | Impossible de joindre le relais |
| origine refusée | Impossible de joindre le relais |
| extension non appairée | Impossible de joindre le relais |
| limite GitHub atteinte | Impossible de joindre le relais |
| relais éteint | Impossible de joindre le relais |
| délai dépassé | Impossible de joindre le relais |

**1 texte distinct pour 11 situations.** Un artefact corrompu, une origine
refusée, une clé refusée et un relais éteint étaient indiscernables — et le
seul cas où « le relais est éteint » est vrai demandait de redémarrer une
installation parfaitement saine.

`relayErrorText()` existait déjà et traduisait le code du relais. Elle
n'était **jamais appelée** depuis ce chemin : la deuxième fonction non lue
après `error_kind` (0.7.24).

## Le second défaut, trouvé en corrigeant le premier

`unknownRelayError` était écrit `"Erreur du relais : {0}"` dans les dix
langues, alors que `t()` ne substituait ses arguments que dans les valeurs de
type **fonction**. Le `{0}` littéral arrivait donc à l'écran et le code du
relais **jamais** — une sortie qui affichait un placeholder au lieu de ce qu'il
promettait.

`t()` accepte désormais les deux formes : une fonction est appelée, une chaîne
est formatée. `{0}` est le seul placeholder du dictionnaire (mesuré : 600
chaînes, 10 accolades, toutes les 10 sur cette clé).

## Les 19 codes que personne ne pouvait voir

Le check de gate `relay_errors_are_translated` ne lisait que
`relay/server.py`, et seulement sous la forme littérale `"error": "…"`. Or le
chemin de mise à jour lève ses propres erreurs (`RuntimeError`) dans
`relay/updater.py` : **19 codes**, tous non mappés. La surface lisible est
passée de **9 à 20 codes**, et le check aujourd'hui **rouge et nomme** un code
non mappé qu'il laissait passer avant.

Les huit refus d'archive sont regroupés sous une seule cause : dire à un
utilisateur que son téléchargement « n'est pas une extension Manifest V3 » ne
lui apprend rien d'utile. Onze clés i18n nouvelles, dix langues chacune.

## Ce que le harnais m'a appris (trois runs perdus)

- **`relayFetch` est DÉFINI ligne 985, en dessous de `runUpdate`.** Un stub posé
  sur l'objet de contexte se fait voler par la déclaration hoistée du sandbox ;
  le vrai part sur `fetch()`. Les deux doivent être déclarés **dedans**.
- **`bridgeHeaders()` lit `bridgeToken`** : binding manquant, le
  `ReferenceError` est attrapé par le `catch` sous test et se lit comme
  « relais hors ligne ». Le harnais reproduisait le bug qu'il cherchait.
- **`__wrapped__` n'existe pas.** Le décorateur `@check` retourne un bool et
  ne conserve pas la fonction d'origine ; appeler un check frère depuis un
  autre check casse le verdict en `TypeError`. La logique a été extraite en
  fonction nue, le check appelant est un wrapper d'une ligne.

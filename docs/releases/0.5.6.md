# v0.5.6 - a gate that runs before the commit, not a fix per day

Ten releases in a day is a symptom, not a schedule. Every failure we shipped
came from a seam no unit test could see: a version bump that missed
`updates.xml`, an allow-list without GitHub's CDN hostname, a popup that grew
past Chrome's 600px cap, an `Accept` header meant for the CDN sent to the API.
The pieces were tested; the joints were not.

## The gate

`python scripts/acceptance.py` runs 24 checks over those joints - the repo first,
then the live system:

    ok   versions agree everywhere              v0.5.6 in manifest, pyproject, updates.xml, CHANGELOG, notes
    ok   shipped tree is LF everywhere          no CRLF in the shipped tree
    ok   no extension id differs from the pin   every id literal in 74 tracked files is the pinned 32-char id
    ok   the shared secret is absent from the repo
    ok   every language has the same strings    45 keys x 10 languages
    ok   every element popup.js touches exists in popup.html
    ok   the popup still fits Chrome's 600px cap
    ok   relay refuses an unauthorised or foreign caller   401 / 403 / 200
    ok   the release asset downloads and matches its sidecar
    ok   a session round-trips through the real import
    ok   the extension in Comet serves the repo version

`--local` needs no service at all and runs in GitHub Actions on every push. A
check that cannot run (no Chrome, no relay, exhausted GitHub quota) reports
SKIP by name - never a silent pass, never a false failure.

## What the gate found on its first run

- **"undefined" rendered in three languages.** zh, ja and ar were each missing
  `clearConfirm` and `clearedToast`: the tooltip on the clear button and the
  toast after clearing showed the string `undefined`. The old translation test
  checked a hand-picked list of update strings; now the entire key set is
  compared across all ten languages, and every `t('...')` call is resolved.
- **A second 33-character extension id**, in `scripts/verify_extension.py` -
  the script whose `chrome-error://chromewebdata/` output had been worked
  around instead of fixed. Its expected version was also hardcoded to "0.4.3",
  so it reported twelve later releases as broken. Both scripts now share
  `scripts/cdp_utils.py`, which owns the id and validates it.
- **`bridge.py` decoded Windows CLI output as utf-8.** `wsl.exe -l -q` writes
  UTF-16LE, `netstat` writes cp850 on a French install: one garbled the distro
  list, the other killed the reader thread and returned `None`.
- **The relay blamed the wrong thing** when GitHub rate-limited it: "GitHub
  unreachable (RuntimeError)" became "GitHub API rate limit reached (anonymous
  is 60/hour per IP)", with `error_kind: rate_limit`, and the check cache went
  from 60 seconds to 5 minutes to stay inside the anonymous budget.

## Verify it yourself

    python scripts/acceptance.py          # 24 checks, exit 0 when READY
    python scripts/acceptance.py --local  # repo checks only, no network
    python -m unittest discover -s tests  # 111 tests, 1 skipped

111 tests, 1 skipped. Every number in this note comes from a run.
